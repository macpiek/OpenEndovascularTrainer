# Exact first-order evaluation without Hessian

The explicit `order:'gradient'` mode computes the same exact constitutive energy and gradient as the full Exact backend. It retains valid strain, Jacobian, moment, tool-energy and anchored reference-twist diagnostics. It does not evaluate the GN Hessian or moment-weighted strain Hessians, and it does not read, clear, validate or scatter stale Hessian bytes.

The separate exports are generated by the SAME fixed stencil/DAG generator as the full Exact operator. Build-time selection omits the second-order output graph and dead instructions, while the gradient accumulates `sum L*J_a*moment_a` in the same order as the full kernel. There is no runtime finite difference, strain approximation, moment threshold, diagonal clamp, or omitted derivative of frame transport/reference twist. The combined kernel is673455bytes; the one/two-tool first-order exports have3376/4138 symbolic nodes and229/250 live locals, compared with27865/32708 nodes and810/947 locals for the full Exact exports.

## API and stale-H contract

- `Exact.evaluateCompositeElement(args, localWorkspace, {order:'gradient'})`.
- `assembleCompositeChain(data, chainWorkspace, {order:'gradient'})` requires explicit `elementBackend:'wasm-exact'`.
- Omitting the third argument preserves the existing full-H default. Unsupported order values throw; other Chain backends reject gradient-only instead of silently computing a Hessian.
- Gradient-only results set `hessianValid:false` and `evaluationOrder:'gradient'`. The Hessian array retains its old bytes and must not be consumed.
- Every full assembly invalidates the previous H before validating/evaluating input and sets `hessianValid:true` only after successful completion. Errors therefore cannot leave a stale matrix marked valid.
- `solveCompositeChainIncrement` rejects a Chain with `hessianValid===false`, even if its matrix bytes look finite. The parent owns the equivalent Mixed guard and TimeStep integration. Existing raw/manual Chain buffers without the flag retain their prior compatibility contract.
- A newly created Chain has a valid empty zero constitutive contribution; after an explicit gradient-only evaluation, only a successful full assembly makes its H valid again.

The parent must request a fresh full Hessian before another Newton direction after a first-order trial. A first-order commit/certificate must retain every original energy, force, torque, length, wall and history check; this patch performs no timestep or certificate changes. InertiaCache still scatters its full H and remains parent-owned; integrating a first-order path there may remove additional unnecessary work. No TimeStep, Mixed, InertiaCache, original JS Element or Fast/GN source was edited in this patch.

## Short whole-Chain probe

`scripts/physics/benchmark-composite-gradient.mjs` measures the complete constitutive assembly and scatter of65/128-node chains, with a shared3D centerline, two declared constant anisotropic materials, different material scales, nonzero prestress and winding. Workspaces are reused. Four warmups precede eight alternating measured pairs. The independent JS parity check and fixture preparation are outside timing. Both arms receive identical data; a NaN H sentinel proves the first-order mode never touches the stale matrix. Source hashes before/after match.

| Nodes | Full Exact E/g/H median | Gradient-only E/g median | Speedup |
|---|---:|---:|---:|
| 65 | 1.293ms | 0.118ms | 10.92× |
| 128 | 2.406ms | 0.303ms | 7.94× |

Every measured energy and gradient matches both full Exact and the JS oracle with zero maximum difference; gradient bytes are additionally checked identical to full Exact. All stale-H sentinel bytes remain unchanged. Raw samples, first warmups, workspace construction and source hashes are in `reports/composite-gradient-mode.json`.

This measures one constitutive evaluation. It does not establish an accepted-dt cost or60FPS. The expected integration benefit is removal of unnecessary expensive full-H evaluations during fresh commit/certification and line-search checks; a full operator is still required for every actual Newton direction. No all-moments-zero optimization was combined with this patch.
